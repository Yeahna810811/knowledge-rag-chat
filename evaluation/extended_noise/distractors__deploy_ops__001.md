泄漏的 Pod 可以把整个节点的内存吃光，导致同节点上的其它服务一起被驱逐。

## 网关与限流

对外暴露 API 时，网关层要统一处理认证、限流、日志和熔断。
限流建议按用户维度而不是按 IP 维度——多个用户共用出口 IP 的场景下，
按 IP 限流会误伤正常用户。

熔断的目标是防止下游故障向上游传导。当依赖的大模型 API 连续失败时，
快速失败并返回降级答案，比让用户一直转圈要好。熔断器的三个状态
（关闭、打开、半开）里，半开状态的探测策略最容易写错：
必须在半开状态限制放行流量，否则一恢复就把下游再次打垮。

## 可观测性三件套

日志、指标、链路追踪。日志要用结构化格式（JSON），并带上统一的
请求 ID，否则跨服务排障时无法把一次请求的日志串起来。

指标方面，除了 CPU、内存这类基础指标，业务指标更有价值：
问答接口的 P95 延迟、检索命中率、模型调用失败率、平均召回块数。
其中「平均召回块数」如果被塞满了上限，说明 top_k 设小了；
如果长期远小于上限，说明知识库覆盖不足。
