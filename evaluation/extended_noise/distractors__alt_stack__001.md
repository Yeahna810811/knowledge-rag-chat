ad 的过滤检索——在需要按部门、按权限过滤文档的
企业级场景里，这个能力比纯向量相似度更重要。

还有一条路线是直接使用传统搜索引擎的向量插件，例如 Elasticsearch 8.x 的
dense_vector 字段配合 kNN 查询。好处是可以把关键词检索和向量检索放在同一个
引擎里完成，不用维护两套数据；代价是向量检索的性能不如专用向量库。

## 向量量化与内存优化

当向量规模上到百万级，原始 float32 向量的内存占用会成为瓶颈。常用的压缩手段是
乘积量化（PQ），把高维向量切成若干子空间分别聚类，用聚类中心的编号代替原始向量，
可以把内存降到原来的 1/16 甚至更低。代价是召回率下降，通常需要配合
过召回 + 精确重排的两段式流程，先取回 4 倍候选再做精排。

## 嵌入模型选型

英文场景下 OpenAI 的 text-embedding-3-small 是常见基线，输出 1536 维。
它的优点是 API 稳定、无需本地部署；缺点是数据要出网，且按 token 计费。
