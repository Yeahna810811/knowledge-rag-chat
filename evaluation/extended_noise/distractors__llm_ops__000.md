# 大模型选型与成本控制（另一个项目的实践）

说明：本文档是干扰语料，描述另一套系统的选型记录，不代表本项目现状。

## 模型能力对比

在需要复杂推理的任务上，GPT-4o 和 Claude Opus 仍然领先开源模型一截，
尤其是多步推理、指令遵循和长上下文理解。但它们的单价较高，
在问答这种高频短请求场景里，成本会快速累积。

国产模型里，DeepSeek-V3 在代码和数学上表现突出，且 API 价格显著低于同级别
闭源模型；Qwen 系列的中英双语能力均衡，生态工具链完善。选型的实践经验是：
先用最强的模型把 prompt 和业务效果调到位，再逐级降配到更便宜的模型，
每一步都用同一份评测集验证效果损失，而不是一上来就为了省钱选小模型。

## 上下文窗口与长文档

长上下文模型（128K 甚至 1M）看起来可以「把整本书塞进去」，但实际使用中有两个坑：
一是注意力衰减，模型对位于上下文中部的内容关注度明显低于开头和结尾；
二是成本和延迟随长度线性增长。所以长上下文并不能替代检索,
它更适合「已经定位到少量候选文档之后」的精读阶段。
