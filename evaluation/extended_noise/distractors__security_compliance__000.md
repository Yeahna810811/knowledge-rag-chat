# 安全与合规实践（干扰语料，与本项目无关）

说明：本文档为干扰语料，描述一套假想系统的安全设计，用于检验检索抗干扰能力。

## 认证与鉴权

认证解决「你是谁」，鉴权解决「你能做什么」。两者必须分开设计。
内部系统常见做法是接入企业统一身份，用 OIDC 或 SAML 完成单点登录，
避免在多个系统里各存一份密码。

接口鉴权建议用短期令牌加长期刷新令牌的组合。
短期令牌有效期设在十五分钟到一小时，即使泄露影响窗口也有限；
刷新令牌存储在服务端并可主动吊销。令牌里不要塞业务数据，
它应当只是一个身份标识。

## 密钥管理

API 密钥绝不能写进代码仓库。即使私有仓库，也有人员流动和权限配置错误的风险。
正确做法是放在密钥管理服务里，运行时动态注入。

密钥要定期轮换，并且支持平滑过渡：新旧密钥同时有效一段时间，
等服务全部切换后再吊销旧密钥。不平滑的轮换必然造成线上事故。

## 注入攻击防护

用户输入不可信是安全的第一原则。SQL 注入靠参数化查询防住，
命令注入靠白名单校验防住，而大模型应用还有一类新问题：提示词注入。
