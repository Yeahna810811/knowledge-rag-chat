# 前端工程实践（另一个项目的记录）

说明：本文档是干扰语料，描述另一个前端项目的做法。

## 框架选型

组件化框架的核心价值是让状态变化和界面更新解耦。
开发者描述「状态是什么样」，框架负责把变化同步到界面。
这比手动操作 DOM 的方式在复杂应用里维护成本低得多。

响应式数据有两种主流实现：基于依赖收集的细粒度更新，
和基于虚拟树对比的粗粒度更新。前者更新精确但需要编译时处理，
后者心智负担小但每次要重新计算整棵子树。
在表单密集的应用里前者优势明显，在展示型页面里两者差别不大。

## 状态管理

组件内部状态用局部状态就够了，跨组件共享才需要全局状态库。
过早引入全局状态会让简单问题复杂化——
一个只被两个组件用到的数据放进全局库，反而多了一层间接性。

全局状态要按领域拆分模块，而不是把所有东西塞进一个巨大的对象。
按领域拆分后，修改一个模块不会意外影响另一个模块，
也便于按需加载。
