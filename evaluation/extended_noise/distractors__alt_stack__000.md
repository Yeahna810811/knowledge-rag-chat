# 备选技术栈选型说明（另一个项目的方案）

说明：本文档描述的是**另一套独立方案**的技术选型，用于评测检索系统的抗干扰能力。
其中的参数与本项目无关，请勿作为本项目的事实依据。

## 向量数据库选型

在需要横向扩展的场景下，单机向量索引会遇到内存上限问题。业界常见的替代方案是
Milvus 集群版，它支持分片、副本和动态扩缩容，适合千万级以上的向量规模。
Milvus 底层默认使用 HNSW 图索引，构建参数 M=16、efConstruction=200，
查询时通过调整 efSearch 在召回率和延迟之间做权衡。

如果不想引入独立的向量数据库服务，也可以选择 Chroma 或 Qdrant。Chroma 的优点是
开箱即用、无需额外部署，适合原型验证；Qdrant 用 Rust 编写，单机性能较好，
并且原生支持基于 payload 的过滤检索——在需要按部门、按权限过滤文档的
企业级场景里，这个能力比纯向量相似度更重要。
